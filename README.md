# AI 教材教具設計工作室

適合特殊教育師資生進行中重度障礙學生教材教具的 AI 輔助設計作業。學生使用 GitHub Pages 一頁式網站；教師從私人 Google Sheets 追蹤最新成果、每次存檔歷程和思辨紀錄。學生自行前往 ChatGPT、Gemini、Claude 等服務生成構想與四張圖片，再貼回或上傳本站。網站不會直接呼叫付費 AI API。

## 專案檔案

| 檔名 | 作用 |
|---|---|
| `index.html` | 學生一頁式網站（六個階段） |
| `styles.css` | 網站樣式、手機版排版 |
| `app.js` | 自動存草稿、動態 Prompt、圖片壓縮、雲端同步與回收確認 |
| `config.js` | 填入 Google Apps Script 的 `/exec` 網址；**不要在此放密碼** |
| `Code.gs` | 貼進 Google Apps Script 的後台程式碼 |
| `examples/` | 「投球訓練機」AI 圖像示範，供學生進行圖片可行性檢核 |

## 第 1 步：建立教師的 Google Sheets 與私人圖片資料夾

1. 在 Google Drive 建立一份新的 Google 試算表（例如 `AI教材教具設計_115學年度`）。
2. 從網址 `https://docs.google.com/spreadsheets/d/試算表ID/edit` 複製 **試算表 ID**。
3. 在 Google Drive 建立一個私人資料夾（例如 `教具設計_學生上傳圖片`），**不要設定「知道連結的任何人都可以存取」**。
4. 從資料夾網址 `https://drive.google.com/drive/folders/資料夾ID` 複製 **資料夾 ID**。
5. 請不要將整張試算表公開給學生；老師自己的 Google 帳號須能編輯該表及寫入該資料夾。

## 第 2 步：建立 Apps Script 後台

1. 在剛建立的試算表中，選「擴充功能 → Apps Script」。
2. 打開 `Code.gs`，完整複製進 Apps Script 編輯器，儲存。
3. 在 Apps Script 左側「專案設定（齒輪）→ 指令碼屬性（Script properties）」新增三組屬性：

   | 屬性名稱（完全一致） | 內容 |
   |---|---|
   | `SPREADSHEET_ID` | 第 1 步的試算表 ID |
   | `IMAGE_FOLDER_ID` | 第 1 步的 Drive 圖片資料夾 ID |
   | `CLASS_CODE` | 自訂給學生的課程提交碼，至少 8 個字元，建議 10–16 字且不易猜測 |

4. 回到 Apps Script 程式編輯器，在上方函式選單選 `setup`，按「執行」。首次會需要授權使用 Google Sheets 與 Google Drive，使用你管理課程的帳號授權。
5. 回到試算表，確認自動出現四個頁籤：`最新學習成果`、`學習歷程`、`回收確認`、`教師看板`。

**注意：** `CLASS_CODE` 是降低非課程填寫的門檻，不是登入認證或防止惡意提交的完整安全機制。適合一般課堂作業；如要蒐集真實個案機敏資料，應改用具身分驗證的校內系統。

## 第 3 步：發佈 Apps Script 網路應用程式

1. 按右上「部署 → 新增部署作業」。
2. 類型選「網路應用程式（Web app）」。
3. **執行身分：我（老師）**。
4. **誰可以存取：任何人**（需讓學生在 GitHub Pages 直接提交；若學校 Workspace 限制匿名存取，請洽管理員或使用校內替代方案）。
5. 部署並完成授權，複製以 `/exec` 結尾的「網路應用程式網址」。**不要用 `/dev` 網址**。
6. 如有日後修改 `Code.gs`，需到「管理部署作業」編輯目前部署並選用**新版本**，儲存後才會更新公開執行的程式。

## 第 4 步：設定 GitHub Pages

1. 把 `index.html`、`styles.css`、`app.js`、`config.js`、`examples/` 上傳到 GitHub 的同一個 Repository 根目錄；也可以直接上傳壓縮檔解壓後的整個資料夾內容。
2. 在 `config.js` 修改一行：

   ```js
   window.APP_CONFIG = {
     title: 'AI 教材教具設計工作室',
     scriptUrl: 'https://script.google.com/macros/s/你的部署ID/exec'
   };
   ```

3. Repository → **Settings → Pages → Deploy from a branch** → `main` → `/(root)`，儲存。
4. 學生網址通常為 `https://你的帳號.github.io/儲存庫名稱/`。
5. 網站右上角應顯示「已設定後台網址」；這表示網址格式已設定，**不代表已通過收件測試**。

> 最重要：不要把真正的 `CLASS_CODE`、試算表存取權、老師 Google 密碼寫在 GitHub 公開檔案。`Code.gs` 放 GitHub 也只能是目前附的「不含秘密」原始版本。實際的三項屬性只留在 Apps Script 專案設定中。

## 第 5 步：完整收件測試（務必做一次）

1. 打開 GitHub Pages 網站。先填寫「班級／組別、學號／作品代碼、姓名」。
2. 在右側輸入你設定的課程提交碼。
3. 按「儲存本階段至老師後台」。
4. 只有看到「**Google Sheets 已確認階段存檔**」才算真的成功；單純送出請求不算完成。
5. 查看 `回收確認` 是否出現 `OK`，`最新學習成果` 是否出現學生一筆資料，`學習歷程` 是否也新增一筆。
6. 修改部分文字，再同步一次。`最新學習成果` 應更新同一列；`學習歷程` 應新增第二列並顯示「本次修改欄位」。
7. 到第三階段上傳一張圖片，再同步一次；老師應可從 Sheet 圖片欄位連到私人 Drive 圖片。
8. 最後測試「正式繳交」前的漏填欄位提示，並確認只有完整作品能正式繳交。

如果回收確認顯示錯誤，請檢查：

- 課程提交碼是否正確、程式屬性名稱是否完全相同。
- 是否選了 `setup` 並授權成功。
- 是不是用了 `/dev` 而非 `/exec`。
- Apps Script 是否以老師身分執行、網路應用程式是否允許學生存取。
- 最新修改是否**重新部署成新版本**。
- 如果沒有確認訊息，檢查 Apps Script 左側「執行項目（Executions）」是否有錯誤，再查 `回收確認` 頁籤。
- 學校或瀏覽器的跨網站追蹤／腳本政策，可能阻止收件確認；學生仍可「匯出備份」交給老師，**不能因按過送出就推論已成功收件**。

## 老師從後台可以看到什麼？

| 頁籤 | 主要用途 |
|---|---|
| `最新學習成果` | 每組／每位學生一列，包含所有階段資料、選擇理由、AI 疑慮、圖片檢核、製作問題、實作修正及最終反思；末六欄可直接留下教師回饋和四項 1–4 分評閱 |
| `學習歷程` | 每次按階段儲存就新增一列，同時保留完整的階段快照與「本次修改欄位」；可檢視設計判斷如何逐次改變 |
| `教師看板` | 自動統計開始件數、正式繳交、目前階段、是否有留下 AI 質疑、圖像檢核、實作修正與拒絕 AI 的理由 |
| `回收確認` | 系統確認記錄，不包含學生作業內容；用來驗證每一筆請求是否真的落表 |

「教師看板」的有／沒有是**填寫證據統計**，不代表學生思辨品質高低，也不應當成自動評分。評分仍由教師閱讀原始內容後作專業判斷。

## 學生使用流程

1. 需求分析：描述學習對象、已有能力、支持、生活化目標。
2. AI 創意發想：複製網站自動產生的 Prompt 到 AI，貼回三案、比較及選擇理由。
3. 四張設計圖：同一套教具的完整外觀、結構分解、學生操作、製作步驟圖；可上傳圖片（自動壓縮）或貼連結，並指出圖中不合理之處。
4. 製作與教學：寫材料、預算、尺寸、步驟、安全、提示與評量。
5. 試作與修正：記錄紙板模型或實體教具測試結果；清楚區分觀察與推測。
6. 思辨與反思：保留採用／拒絕 AI 建議的理由及技能遷移方案。完成必填資料與四張圖後可正式繳交。

本站**沒有內建生成式 AI API**，也不會替學生撰寫答案或把 Prompt 自動送給第三方平台。圖片可從 AI 網站下載後，回到本頁上傳；外部圖片連結需能讓老師開啟。

## 資料保存、隱私與操作限制

- 網站自動暫存文字與未同步圖片到目前瀏覽器 `localStorage`；**跨裝置不會自動取得舊草稿**，需由學生「匯出備份 → 匯入備份」。公用裝置請在離開前清除本機草稿。
- 提交碼僅儲存於當前分頁的 `sessionStorage`，不放入匯出的 JSON 草稿檔。
- 每張上傳圖片在瀏覽器壓縮為 JPEG（目標約 350 KB 內），上傳後存到老師指定的私人 Drive 資料夾。原始圖片檔案不會隨頁面公開在 GitHub。
- Google Drive 上傳的檔案**不會自動設為公開**。如果你的 Google 帳號和資料夾政策不允許 Apps Script 寫入，需先解決權限。
- 請使用虛構／去識別化學生案例；避免學生姓名、特教鑑定資料、未授權照片、真實個案情況等敏感資訊。授權學生姓名是指**師資生的課程作業辨識資訊**，不是被服務學生的姓名。
- Apps Script 部署為任何人可存取，具有濫用、配額與垃圾資料風險；長期或跨校公開使用請加上更嚴格的認證與存取控管。
- Google Apps Script、Google Sheets、Drive 均有使用配額；不宜做大型照片庫或高頻同步。學生按階段儲存即可。
- 若需修改欄位名稱，請同時評估既有 Google Sheets 資料；不要隨意覆寫／刪除 `學習歷程` 和 `回收確認`。

## 延伸教學評量參考

教師可在 `最新學習成果` 最後六欄用 1–4 分評閱以下面向：

- **需求分析**：是否由個別能力、情境與目標出發，而非以障礙標籤設計。
- **AI 批判思辨**：是否能比較方案、辨認生成內容問題，提出具體反駁或查核。
- **設計與實作**：是否能由圖像走向可製作、安全、可操作的實物並根據測試修正。
- **反思與類化**：是否能說明自身判斷、學生自主性、技能類化以及不同需求下的設計轉化。
